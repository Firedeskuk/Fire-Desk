## 3. Decisions made without asking

1. Branch: the session was started on claude/night-1-task-yy281e, the task says feat/mvp-night-1. All work is on feat/mvp-night-1. Neither branch could be pushed.
2. Commit messages are one line, as CLAUDE.md section 3 asks, without the tool's usual co-author trailer lines.
3. npm install failed with an npm arborist error (Cannot read properties of null, reading edgesOut) caused by peer dependency resolution. Installed with --legacy-peer-deps and committed .npmrc with legacy-peer-deps=true, so npm install behaves the same for everyone.
4. @testing-library/react was left out. It needs @testing-library/dom at runtime, which is not on the allowed list, so it could not work. Tests use vitest with fake-indexeddb and jsdom only.
5. Row types in lib/supabase/types.ts are type aliases, not interfaces, because supabase-js needs index signature compatible rows to type query results.
6. RouteGuard trusts the local profile only and never calls Supabase, so downloaded buildings open offline after the access token expired. The sync worker reports an auth problem separately in the pill.
7. lib/local/session.ts keeps the profile and device id in localStorage (synchronous, works during the first render), the Dexie session table exists for the future native shell and is written through setSessionValue.
8. The photo upload row does not depend on the finding row, only the finding_photos row depends on the upload (and on the finding row when the screen passes it). Storage and table writes are independent on the server.
9. The worker never imports supabase-js directly: triggers.ts injects the real client once, tests inject a fake.
10. The office building register lives at /office/buildings because /buildings is the inspector list and two pages cannot share one path across route groups. The header link is still labelled Buildings.
11. Number questions use inputMode decimal (not numeric) so 3.5 mm can be typed on iPhone.
12. Assets with status removed or replaced are hidden from the dashboard counts and the office Doors column, and still listed in the field.
13. Floor plan replace writes a new storage key floorplans/{building_id}/{floor_id}/{new id}.{ext} (upsert false) because the database only has insert and select policies on storage.objects, and a new key also makes phones refetch the plan on the next refresh. Only PNG and JPEG are accepted, the phone renders the plan in an img tag.
14. Quote total is read back from quote_lines.final_price after the insert and summed in whole pence, so quotes.total always equals the database lines. A quote whose lines failed to insert is removed again.
15. Mark done on a work item is disabled until at least one photo after exists (the task said "marks items done with a photo after").
16. Offline route shells and the after write sync trigger, described in section 1.
17. Unit m2 for the fire batt price item (the task said per square metre).
18. playwright-core was installed only inside the session scratchpad to run the Chromium check. It is not in package.json. scripts/offline-check.mjs explains how to run it with `npm install --no-save playwright-core`.
